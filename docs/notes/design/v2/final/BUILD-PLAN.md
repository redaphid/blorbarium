# Blorbarium alife v2: build plan

Each unit is small, ends in a check someone can run, and is ordered by fun per cost. "Gates" means the depth branch's `tools/learnsim/gates.sh` (stack check, `native`, `native_san`, e2e). Every unit runs it. "Hash" means the 24-hour replay hash is re-blessed in that unit on purpose and nowhere else. An e2e scenario lands as `knownFailing` in the unit that adds it and must flip there. Its next-day probe flips with it.

The **Depends** column names in-flight work that must land first:

- **depth**: u1 rebalance, u2 forgetting and heirlooms, u35 rot, tilt and time, u4 interrupts and memory span.
- **thoughts**: the marquee registry and `OracleGene`.
- **dialogue**: the offline line generator.
- **hw**: unit 20 on the real 1.28.
- **visual-center**: walk-home and the foresee face.

Sizes: S is under 150 lines plus tests, M is 150 to 500, and L is over 500.

## Notes for whoever builds it

- **U0 is coordination.** Do it while the three branches are still uncommitted. It costs minutes now and a gene-type migration later.
- **The RAM gate moves to U4.** It is the first unit that grows the keepsake. Move the save transient to PSRAM there through a cold-buffer allocator in `seams.h`. Keep the canvas internal.
- **Feel checks on the device.** U2 (the marble's feel), U3 (presses and holds) and U11 (keeper) each end with a 10-minute play session on the real board, after their automated checks pass. If a constant changes, record it in `DEVIATIONS.md`.
- **The gyro.** No unit depends on it. Spin is an extension row (`DESIGN.md` section 10) once unit 20's IMU read bug is fixed.
